# 新增 3D 食物展示制作单

目标：以菜单为展示载体，扩展可独立复制的真实 GLB 资产。无需真实餐厅运营、支付、库存或后厨闭环。

用户指定制作顺序：炸鸡 → 饮品 → 甜点。参考图模型：image / gpt-image-2.5。

## 菜单范围

保留现有汉堡、披萨、薯条，新增黄金炸鸡块、补齐已有鲜柠气泡饮的真实模型、新增巧克力布朗尼。菜单增加甜点分类。沿用当前菜单视觉和查看/旋转/体验入口，不重做点单业务。

未就绪资产不得注册为可用虚拟试吃菜品。已有模型不作为新增食物的替身。价格与选项仅为展示数据。

## 1. 黄金炸鸡块

- 完整份为六块无骨炸鸡，低矮分布、互不穿插，主体跨度约160 mm，单块约40 mm。
- 四阶段：6块 → 4块 → 2块 → 1块；后续阶段保留同一批鸡块的位置、形状、纹理及尺寸，优先从完整模型删除独立组件，避免四次独立重建引起漂移。
- 金黄不规则酥皮，烘烤色差自然；不附盘子、纸张或装饰。
- 每阶段3次交互，合计12次，沿用现有固体食物交互。
- 验收：数量正确、底部封闭、无悬浮碎片、背面无正面复制、阶段间剩余鸡块一致。

## 2. 鲜柠气泡饮

- 透明矮杯，淡黄色气泡饮、冰块、柠檬片；杯体外形与尺寸四阶段完全一致。
- 四阶段液位：约85% → 60% → 35% → 10%，杯体保留；液位比例是设计目标，交付时按实际几何测量。
- 杯体、液体、冰块、柠檬应是独立命名组件，透明度与透射尽量采用标准 glTF PBR 扩展。
- 透明容器优先参数化构建以保持液位和杯体一致；参考图用于外观指导，避免图生3D直接把透明杯烘焙成不透明块。
- 饮用反馈应保持杯体稳定、避免固体碎屑和咬断音效。需为饮品添加可独立选择的交互类型，兼容既有固体食物。
- 验收：杯壁厚度合理、液面闭合、无深度排序明显错误，浅色和深色背景都能看清。

## 3. 巧克力布朗尼

- 单块布朗尼，约80×65×35 mm；巧克力薄脆表层、湿润蛋糕切面，不加容易漂移的散落装饰。
- 四阶段：完整 → 剩约3/4 → 剩约1/2 → 剩约1/4；同一方向连续消耗，轮廓、表皮与切面一致。
- 切面需要真实几何与独立材质，不能只更换正面贴图。底面应为蛋糕烘焙底面。
- 每阶段3次交互，合计12次。
- 验收：顶面/切面/底面材质区分，所有切口闭合，剩余体积递减，不随阶段放大模型。

## 通用交付

每类进入 assets/<food-id>/：参考图、可用来源文件、制作脚本、四阶段GLB、mobile/desktop变体、封面、catalog元数据、哈希及验收报告。资产须内嵌纹理，可独立加载；记录所需glTF扩展。预览和阶段切换不得改变旧三类食物。

专属音效只有在可用来源与授权明确时接入；不把汉堡音效当作饮用音效。
