# 食刻 UI 设计审批规范

## 强制审批门禁

1. **所有设计改动，无论大小，都必须在实施前取得用户对具体方案的明确认可。**
2. 默认仅进行分析、调研和方案设计，不修改产品界面、样式、组件、交互逻辑或视觉文案。
3. 提交方案时，清楚列出改动页面、视觉方向、布局、组件、交互与响应式影响。能用示意图或预览辅助时，应标明“仅供评审”。
4. 用户说“继续”“开始设计”“优化一下”或提供参考链接，不等于批准实施。
5. 只有用户对方案作出“确认”“认可”“按此实施”等明确回应后，才可修改获批准的范围。
6. 批准后仍须严格按方案实施。新增设计、替代方向或批准范围外的改动，需要重新询问。
7. 不得把测试、修复、重构作为绕过审批、顺带改变视觉或交互的理由。
8. 实施完成后，展示实际结果并请求用户验收；验收前不自行扩大改动。

## 推荐工作流

1. 阅读项目内容与现有界面，保留核心玩法、3D 食物可操作性、加载/错误/完成状态及可访问性。
2. 如提供参考网页，只提炼其风格、节奏和交互语言，不机械复制品牌资产。
3. 提交包含设计目标、设计系统、关键页面、交互说明及移动/桌面适配的提案。
4. 等待明确批准。
5. 在批准范围内实施并验证。
